# Meta-Team 演示指令（按块复制）

装好 DSH CLI 和插件 `v0.1.1` 后，双击本目录的 **start-macos.command**，使用它新打开的 DSH 网页。每个代码块是**一条消息**，一次只复制一个框，不要把编号或标题发进聊天。两轮之间**只开新聊天，不重启 DSH**。

## 确认从零开始

```text
/meta status
```

应看到 `head: v000000` 和 `phase: not-started`。

## 第一轮：创建任务并发送对账题

```text
/meta begin {"id":"demo-first","task":"对账并独立复核调整后的剩余差额"}
```

看到 `execution` 后，在**同一个聊天**发送：

```text
请对比下面两份流水，列出逐笔差异和两表净差。

A 表：A01=120，A02=80，A03=50
B 表：A01=120，A02=75，A04=40

对仅在 B 表出现的 A04，分别计算 A 表补记 40、或 B 表冲销 40 后的剩余差额。只做假设计算，不判断实际该怎么处理。

请把初稿交给 reviewer 独立复核，收到回复后再用 finalize_task 提交最终结果。
```

等最终稿出来，再发送：

```text
/meta status
```

看到 `awaiting-feedback` 才能提交反馈。参考答案：A 合计 250，B 合计 235，净差 +15；两个假设下的剩余差额都为 +55。

## 第一轮：按实际结果提交反馈

**仅当终稿正确，且 reviewer 确实建议区分缺失和零金额**，复制这条：

```text
/meta feedback {"success":true,"summary":"最终对账正确：净差为15，两种假设下的剩余差额均为55。reviewer 建议明确说明，缺失项按0参与运算，不等于原表存在一条金额为0的记录。请反思如何在第一次交接时就把这个口径讲清楚，同时保留 reviewer 的独立复核。"}
```

**如果终稿正确，且本轮没有发现上述问题或其他明确问题**，可复制这条，让团队总结有效做法，不虚构失败：

```text
/meta feedback {"success":true,"summary":"最终对账正确：净差为15，两种假设下的剩余差额均为55。请根据实际交接记录，总结本轮哪些做法帮助 reviewer 独立核对，并保留真正有用、可复用的做法。没有发现的问题不要当成已经发生。"}
```

如果本轮发现的是别的问题就改 `summary`；如果最终稿有错误，把 `success` 改成 `false`，写明实际错误。两条反馈只选一条，不要都发。发完等团队反思，再检查：

```text
/meta status
```

看到 `complete` 再进入第二轮。这个状态里的 `version: v000000` 指第一轮的**起始版本**，不是刚保存的新版本。

## 第二轮：换新聊天，发送新题

在**同一个 DSH 网页**里新建聊天，发送：

```text
/meta begin {"id":"demo-second","task":"对比新流水并独立复核调整后的剩余差额"}
```

看到 `execution` 后，发送：

```text
请对比下面两份流水，列出逐笔差异和两表净差。

A 表：B10=90，B11=45，B12=30，B14=0
B 表：B10=90，B11=40，B13=25

对仅在 B 表出现的 B13，分别计算 A 表补记 25、或 B 表冲销 25 后的剩余差额。只做假设计算，不判断实际该怎么处理。

请把初稿交给 reviewer 独立复核，收到回复后再用 finalize_task 提交最终结果。
```

等最终稿出来，再发送：

```text
/meta status
```

展示 `version: v000001`，然后看 **implementer 首次发给 reviewer 的消息**是否体现了第一轮保存的改动。如果保存的是「区分缺失和零金额」，就看它是否主动指出：B14 金额差是 0，但只在 A 表出现。第二轮参考答案：净差 +10，两个假设下的剩余差额都为 +35。演示到这里可以结束，不必发第二次反馈。
